# `o1next.pretty` — the footprints this board needs that no library carries

A **KiCad footprint library**, and the reason it exists rather than the footprints
being generated into the schematic: these are *parts*, not drawings. A footprint is
a piece of engineering somebody else may need, it is worth reviewing on its own,
and one of the ones this board wants **should go upstream**.

The rule for what belongs here:

- **the part exists and is buyable**, and
- **its footprint is not in KiCad's libraries or the vendor's own KiCad library**,
  and
- we have the datasheet's land pattern to draw it from.

Nothing goes in here as a guess. A footprint that is nearly right is a board that
does not fit, which is worse than a missing one — a missing one is visibly undone.

## What is meant to be here

| Footprint | Part | Why it is not upstream | Publishable to |
|---|---|---|---|
| `ESP32-S2-MINI-2U` | Espressif ESP32-S2-MINI-2U-N4 | **The Espressif KiCad library carries `ESP32-S2-MINI-1`, `-1U` and `SOLO-2U` and no `-2U`** — while MINI-1/-1U are NRND, which is why this board uses the -2U. The land pattern is datasheet §10.1 (v1.4) / §7.2 (v1.1), and Espressif publishes source files for it. | **`espressif/kicad-libraries`** — this is the one that should go back |
| `LED_SunLED_XZM2CRK168WA` | SunLED XZM2CRK168WA | A 1.8 × 0.6 mm **right-angle** chip LED. KiCad's nearest is `LED_Kingbright_APA1606_1.6x0.6mm_Horizontal`, which is a different part. | `LED_SMD`, if the naming convention is met |
| `USB_C_SameSky_UJ32-C-H-G-DSMT-1-P24-TR` | Same Sky UJ32-C-H-G-DSMT-1-P24-TR | 24-contact USB 3.2 Gen 1 receptacle. Same Sky publishes a PCB footprint beside the datasheet. | possibly `Connector_USB` |

`fp-lib-table` beside this directory registers it as the `o1next:` library, so the
schematic refers to `o1next:ESP32-S2-MINI-2U` and KiCad resolves it from the
project rather than from a global install. **That is what makes these separately
publishable**: the file is self-contained, it is not generated, and moving it into
another library is a copy.

## The board this is for

`hardware/wifi-comm-pac/` — the O1NEXT WiFi COMM PAC (issues **#324**, **#325**,
part of **#56**). The schematic is generated by `gen_wifi_comm_pac_sch.py`, whose
`FOOTPRINTS` table will name these as `o1next:<name>`.

## What is needed to finish each

Every one is blocked on **reading a land pattern that is vector art inside a PDF** —
it extracts as dimension labels without their geometry, and it is not an embedded
raster image, so neither a text extractor nor an image reader can recover it:

- **`ESP32-S2-MINI-2U`** — SnapEDA has the finished KiCad footprint for
  `ESP32-S2-MINI-2U-N4`; it is behind a bot check (403 with a browser user-agent).
  Espressif's own land-pattern source files (§10.1) are the other route.
- **`LED_SunLED_XZM2CRK168WA`** — datasheet page 3, "Recommended Soldering
  Pattern", units mm, tolerance ±0.1.
- **`USB_C_SameSky_...`** — Same Sky's published PCB footprint, or page 3 of the
  datasheet, "Recommended PCB Layout".

Each datasheet is cited above, so whoever picks this up needs the figure and
nothing else.
